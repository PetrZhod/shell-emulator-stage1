# Эмулятор оболочки. Вариант 10 — все пять этапов

Ветка stage-5 содержит итоговую программу: GUI REPL, конфигурацию, CSV, JSON VFS и все команды.
Требуется Python 3.10+ с Tkinter; сторонние пакеты не нужны.

## Запуск в терминале ОС из корня проекта

```text
python src/main.py --vfs examples/vfs.json --log logs/demo.csv
python -m unittest discover -s tests -v
```

Можно использовать `run.bat` или `sh run.sh`, передавая те же параметры.
В Visual Studio запускаемый файл — `src/main.py`, рабочая папка — корень репозитория.
Параметры задаются в Script Arguments. Команды эмулятора вводятся в его GUI, не в PowerShell.
GUI содержит приглашение `localhost:~#`, заголовок — имя VFS из JSON.
Ввод делится по пробелам; кавычки, конвейеры и экранирование не реализованы.

## Этапы 1–2: REPL и конфигурация

Параметры: `--vfs PATH`, `--log PATH`, необязательный `--script PATH`.
По умолчанию: `examples/vfs.json`, `logs/commands.csv`, скрипт не задан.
При запуске все параметры видны в консоли и GUI. Относительные пути — от рабочей папки.
CSV дополняется и содержит ровно `command,arguments,username,error`; аргументы — JSON-массив.
Имя пользователя берётся из ОС. Ошибки журнала сообщаются, чужой CSV не перезаписывается.
Путь лога не может совпадать с VFS или скриптом.
Стартовый скрипт — UTF-8/UTF-8 BOM; `#` начинает комментарий Python.
GUI показывает ввод и вывод; при ошибке — файл и строку, затем работа продолжается.
При ошибке чтения скрипт не выполняется частично. Корректный exit останавливает сценарий.
На этапах 1–3 ls/cd были заглушками; в итоговой версии они работают с VFS.

## Этап 3: JSON VFS

JSON содержит `name` и `root`. Каталог: `type: directory` и словарь `children`.
Файл: `type: file` и строка base64 `data`. Образцы формата находятся в `examples`.
Загрузка проверяет JSON, base64, имена и типы узлов; ошибки сообщаются до запуска GUI.
Файлы не распаковываются. Все обычные операции выполняются в памяти.
Новый запуск заново читает исходный JSON: mkdir/cp не сохраняются на диск.
`vfs-init` без аргументов очищает память и физический JSON, сохраняя имя VFS.
VFS по умолчанию после очистки — пустой корневой каталог.

## Этап 4: основные команды

- `ls [-a] [-l] [path]`: сортированные имена; -a включает скрытые файлы;
  -l показывает тип (d или -) и размер в байтах. Флаги можно объединять (-al).
  Размер каталога — 0, системные права и даты не имитируются.
- `cd [path]`: абсолютные/относительные пути, `.` и `..`; без пути — корень;
  `cd -` — предыдущий каталог. Выше корня перейти нельзя.
- `du [-s] [path]`: байты декодированных файлов и суммы каталогов; -s — лишь итог.
- `cal`: текущий месяц; `cal YEAR`: год; `cal MONTH YEAR`: указанный месяц.
  Годы 1..9999, месяцы 1..12, неделя начинается с понедельника.
- `history [N]`: история либо последние N строк; `history -c`: очистка.
  Текущая и ошибочные команды включаются в историю, пустые строки — нет.
- `exit`: закрыть окно без аргументов. Неизвестные команды и неверные аргументы — ошибки.

## Этап 5: изменение VFS в памяти

- `mkdir [-p] path`: создать каталог; -p создаёт родителей и допускает существующий каталог.
- `cp [-r] source destination`: копия файла; -r — независимая рекурсивная копия дерева.
  В существующем каталоге создаётся копия с именем источника. Файл можно перезаписать.
  Слияние существующих деревьев не поддерживается. Нельзя копировать корень, объект на себя,
  каталог внутрь себя или поверх файла. Ошибки выводятся в GUI и CSV.

`ls`, `du`, `mkdir`, `cp` поддерживают `--` для завершения списка флагов.

## Демонстрация и тестирование

`examples/startup.txt` проверяет все команды, поддержанные режимы, ошибки и остановку после exit.
Сценарии `scripts/test_stage5_minimal.bat`, `test_stage5_multiple.bat`, `test_stage5_deep.bat`
передают все три параметра и используют копии JSON в `logs`, не уничтожая образцы.
Минимальная VFS — пустой корень; многофайловая — два файла; глубокая —
`/home/user/docs/readme.txt` (не менее трёх уровней). Отсутствующие пути — проверки ошибок.
Важно: вручную указанный файл VFS физически очищается командой vfs-init.
Настоящий GUI и BAT-сценарии дополнительно проверьте в Windows.
Новые коммиты — Conventional/Scoped; старая история не переписана.
