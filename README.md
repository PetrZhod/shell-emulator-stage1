Эмулятор командной оболочки. Вариант №10.

Этап 1. Графический REPL: разбор ввода на команду и аргументы, команды-заглушки и обработка ошибок.
Этап 2. Конфигурация через параметры командной строки, стартовый скрипт и CSV-лог.
Этап 3. Подключение VFS из JSON-файла и команда `vfs-init`.
Этап 4. Полноценные `ls`, `cd`, `du`, `cal`, `history`.
Этап 5. Команды изменения VFS: `mkdir`, `cp`.

Этап 1.

- Графический интерфейс реализован с помощью Tkinter.
- Заголовок окна содержит имя VFS (на этапе 2 — имя файла из `--vfs`).
- Ввод разделяется на команду и аргументы по пробелам.
- `ls [args...]`, `cd [args...]` — заглушки, печатающие имя и аргументы.
- `exit` — завершение работы; аргументы не поддерживаются.
- Неизвестные команды и неверные аргументы выводят сообщение об ошибке.

Для проверки:

```text
localhost:~# ls one two
Command: ls
Arguments: ['one', 'two']
localhost:~# cd home
Command: cd
Arguments: ['home']
localhost:~# cd one two
cd: too many arguments
localhost:~# unknown
sh: unknown: not found
localhost:~# exit
exit
```

Этап 2.

- `--vfs PATH` — путь к физическому расположению VFS; по умолчанию `vfs.json`.
- `--log PATH` — путь к CSV-логу; по умолчанию `logs/commands.csv`.
- `--script PATH` — путь к стартовому скрипту; по умолчанию не задан.
- При запуске все параметры выводятся в консоль и в GUI, пути показываются абсолютными.
- Все относительные пути считаются от текущей рабочей папки. Пути с пробелами в параметрах запуска заключаются в кавычки.
- VFS на этом этапе не читается и не изменяется. `examples/vfs.json` — только пример пути; загрузка JSON появится на этапе 3.
- В CSV только четыре поля: `command` (команда), `arguments` (аргументы), `username` (имя пользователя ОС), `error` (сообщение об ошибке). При успешном выполнении поле ошибки пустое.
- Повторный запуск дописывает строки в CSV, не дублируя заголовок. Аргументы записаны JSON-массивом внутри CSV-поля. Если остался журнал прежней версии с дополнительными колонками, укажите новый путь через `--log`: старые записи автоматически не изменяются и не удаляются.
- Ошибка создания лога выводится в консоль до запуска GUI. Неподходящий существующий файл не перезаписывается. Совпадение пути лога с VFS или скриптом запрещено.
- Ошибка записи лога во время работы отображается в GUI. Неудавшуюся запись невозможно сохранить в недоступный файл; команда получает статус `1`.
- Стартовый скрипт читается как UTF-8 (включая UTF-8 BOM); пустые строки и комментарии `#` пропускаются. Допускаются комментарии после команды. `#` всегда начинает комментарий: кавычки и экранирование не поддерживаются.
- Команды скрипта и их результаты выводятся в то же окно, что и интерактивный ввод. Используется общий обработчик команд.
- При ошибке команды указываются файл и номер строки, затем выполнение продолжается. Корректный `exit` прекращает скрипт и закрывает окно; последующие строки не выполняются. `exit now` — ошибка, выполнение продолжается.
- Отсутствующий, недоступный скрипт или неправильная кодировка показывают ошибку в GUI; эмулятор остаётся доступным для интерактивного ввода. Файл читается целиком до исполнения, поэтому при ошибке чтения команды не выполняются частично.

Сборка и запуск

Требуется Python 3.10+ с поддержкой Tkinter. Для самой программы сторонние пакеты не нужны.

```bash
python src/main.py
python src/main.py --help
python src/main.py --vfs examples/vfs.json --log logs/demo.csv --script examples/startup.txt
```

На Windows можно запустить `run.bat` или передать ему параметры:

```bat
run.bat --vfs "examples\vfs.json" --log "logs\demo.csv" --script "examples\startup.txt"
```

`run.bat` и `run.sh` переходят в корень проекта. В Visual Studio назначьте `src/main.py` запускаемым файлом и задайте в свойствах проекта рабочую папку — корень репозитория. Аргументы интерпретатора оставьте пустыми; параметры `--vfs`, `--log`, `--script` укажите в аргументах сценария (Script Arguments).

Проверочные скрипты Windows

- `scripts/test_stage2_basic.bat` — все три параметра, успешные команды и ошибки; окно остаётся открытым.
- `scripts/test_stage2_spaces.bat` — все три параметра с пробелами в путях; создаёт тестовые копии файлов внутри `logs/space demo`.
- `scripts/test_stage2_errors.bat` — отсутствующий скрипт (закройте GUI для продолжения), недопустимый путь лога, пропущенное значение параметра и неизвестный параметр.
- `scripts/test_stage2_exit.bat` — остановка скрипта по `exit`. В `logs/exit.csv` не должно быть аргумента `must-not-run`.

Запускайте `.bat` двойным щелчком или из терминала. Каталог `logs` создаётся автоматически и исключён из Git. При повторных запусках учитывайте, что журнал дополняется.

`examples/startup.txt` проверяет `ls`, `cd`, отсутствие аргументов, несколько аргументов, комментарии, неизвестную команду и неправильный `exit`. После него можно вводить команды вручную. `examples/exit.txt` отдельно проверяет успешный `exit` и остановку последующих команд.

Автоматические тесты

Без установки пакетов:

```bash
python -m unittest discover -s tests -v
```

Или через pytest:

```bash
pip install -r requirements-dev.txt
python -m pytest tests
```

Тесты проверяют парсер, старые команды, CSV, пользователя и ошибки, параметры, комментарии, кодировку, номера строк, продолжение скрипта после ошибок, остановку по exit и неизменность VFS. GUI в тестах заменён тестовыми виджетами. Реальное открытие окна и запуск `.bat` нужно проверить в Windows.
