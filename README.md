# Эмулятор оболочки. Вариант 10 — этап 4

Реализованы этапы 1–4: GUI REPL, конфигурация, CSV, JSON VFS и основные команды.
Требуется Python 3.10+ с Tkinter; сторонние пакеты не нужны.

## Запуск в терминале ОС из корня проекта

```text
python src/main.py --vfs examples/vfs.json --log logs/demo.csv
python -m unittest discover -s tests -v
```

`--script PATH` добавляет стартовый скрипт. Можно использовать `run.bat` или `sh run.sh`.
В Visual Studio запускаемый файл — `src/main.py`, рабочая папка — корень репозитория.
Параметры задаются в Script Arguments. Команды эмулятора вводятся в его GUI, не в PowerShell.
GUI содержит приглашение `localhost:~#`, заголовок — имя VFS из JSON.
Ввод делится по пробелам; кавычки, конвейеры и экранирование не реализованы.

## Конфигурация и VFS

По умолчанию: `--vfs examples/vfs.json`, `--log logs/commands.csv`, без скрипта.
Все параметры выводятся в консоль и GUI. Относительные пути — от рабочей папки.
CSV дополняется и содержит ровно `command,arguments,username,error`; аргументы — JSON-массив.
Ошибки журнала сообщаются; неподходящий CSV не перезаписывается; лог не совпадает с VFS/скриптом.
Скрипт — UTF-8/UTF-8 BOM; `#` начинает комментарий. GUI показывает команды и результаты.
Ошибка команды содержит файл и строку, затем работа продолжается. `exit` останавливает скрипт.
При ошибке чтения скрипт не исполняется частично. Ошибки VFS сообщаются до открытия окна.
JSON VFS содержит `name` и `root`; каталог — `type: directory` и `children`;
файл — `type: file` и строка base64 `data`. Образцы формата — в `examples`.
Все обычные операции — в памяти, без распаковки. Новая сессия заново читает исходный JSON.
`vfs-init` без аргументов очищает память и физический JSON до пустого корня, сохраняя имя VFS.

## Команды

- `ls [-a] [-l] [path]`: имена в алфавитном порядке; -a включает скрытые файлы;
  -l показывает тип (d или -) и размер в байтах. Можно объединять флаги (-al).
  Служебный размер каталога — 0; системные права и даты не имитируются.
- `cd [path]`: относительные/абсолютные пути, `.` и `..`; без пути — корень;
  `cd -` — предыдущий каталог. Переход выше корня оставляет в корне.
- `du [-s] [path]`: байты декодированных файлов и суммы каталогов; -s — только итог.
- `cal`: текущий месяц; `cal YEAR`: год; `cal MONTH YEAR`: указанный месяц.
  Годы 1..9999, месяцы 1..12; неделя с понедельника.
- `history [N]`: история или последние N строк; `history -c`: очистить.
  История включает текущую и ошибочные команды, но не пустые строки.
- `exit`: завершить работу без аргументов. Неизвестные команды и неверные аргументы — ошибки.

`ls` и `du` поддерживают `--` для завершения флагов. `mkdir`/`cp` появятся на этапе 5.

## Проверка

`examples/startup.txt` содержит все команды, режимы, ошибки и проверку остановки после exit.
Сценарии `scripts/test_stage4_minimal.bat`, `test_stage4_multiple.bat`, `test_stage4_deep.bat`
передают все три параметра и проверяют пустую, многофайловую и глубокую VFS.
Они работают с копиями JSON в `logs`, поэтому vfs-init не уничтожает образцы.
В глубоком образце есть `/home/user/docs/readme.txt`. Отсутствующие пути в других образцах — проверки ошибок.
Вручную переданный JSON физически очищается командой `vfs-init`: не используйте нужные данные.
Настоящий GUI и BAT-сценарии дополнительно проверьте в Windows.
Новые коммиты — Conventional/Scoped; старая история не переписана.
