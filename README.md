# Этап 2. Конфигурация

Во втором этапе добавлены параметры запуска через argparse, CSV-журнал с пользователем и ошибками,
стартовый скрипт с комментариями Python и проверочные BAT-сценарии Windows.
GUI сохраняет приглашение `localhost:~#`; заголовок содержит имя файла VFS.
Команды `ls [args...]` и `cd [path]` пока заглушки. Неизвестные команды и неверные аргументы — ошибки.
`exit` без аргументов завершает работу. Ввод разделяется по пробелам, без разбора кавычек и конвейеров.

## Параметры

- `--vfs PATH`: физический путь VFS; по умолчанию `vfs.json`.
- `--log PATH`: CSV-журнал; по умолчанию `logs/commands.csv`.
- `--script PATH`: стартовый скрипт UTF-8; по умолчанию не задан.

При запуске все параметры выводятся в консоль и GUI с абсолютными путями.
Относительные пути считаются от рабочей папки. Пути запуска с пробелами заключайте в кавычки.
На этапе 2 VFS ещё не загружается и не изменяется; `examples/vfs.json` — пример пути.

## CSV и скрипт

CSV содержит ровно `command,arguments,username,error`. Аргументы — JSON-массив,
имя пользователя берётся из ОС, при успехе ошибка пустая. Журнал дополняется без повторного заголовка.
Файл с другим заголовком не перезаписывается: укажите новый путь через --log.
Совпадение пути лога с VFS или скриптом запрещено. Ошибки создания лога видны до запуска GUI,
ошибки записи во время работы — в GUI. Недоступную запись сохранить невозможно.

Скрипт читается целиком как UTF-8, включая UTF-8 BOM. Пустые строки пропускаются,
`#` начинает комментарий, в том числе после команды. Кавычки и экранирование не поддерживаются.
GUI показывает и команды, и результаты. Ошибка содержит путь скрипта и номер строки,
затем выполнение продолжается. Корректный exit останавливает сценарий и закрывает окно.
`exit now` — ошибка, а не выход. При отсутствии файла или неверной кодировке показывается ошибка,
команды не выполняются частично; окно остаётся доступным для ручного ввода.

## Запуск

Требуется Python 3.10+ с Tkinter. Для программы и unittest сторонние пакеты не нужны.
В терминале ОС из корня проекта:

```text
python src/main.py
python src/main.py --help
python src/main.py --vfs examples/vfs.json --log logs/demo.csv --script examples/startup.txt
python -m unittest discover -s tests -v
```

В Windows можно запустить `run.bat` с теми же параметрами; в Linux/macOS — `sh run.sh`.
Оба файла переходят в корень проекта. Не вводите python, pip или run.bat в окне эмулятора.
В Visual Studio запускаемый файл — `src/main.py`, рабочая папка — корень проекта;
аргументы интерпретатора пустые, параметры задаются в Script Arguments.

## Проверочные сценарии Windows

- `scripts/test_stage2_basic.bat`: все три параметра, успешные команды и ошибки.
- `scripts/test_stage2_spaces.bat`: все три параметра с пробелами в путях.
- `scripts/test_stage2_errors.bat`: отсутствующий скрипт, недопустимый лог,
  пропущенное значение и неизвестный параметр. Для продолжения закройте открытое окно.
- `scripts/test_stage2_exit.bat`: завершение по exit, последняя команда не должна попасть в журнал.

Каталог logs создаётся автоматически и исключён из Git. При повторных запусках CSV дополняется.
`examples/startup.txt` проверяет заглушки, комментарии, неизвестную команду и неверные аргументы.
`examples/exit.txt` проверяет корректный выход и остановку последующих команд.
Тесты GUI подменяют Tkinter; настоящее окно и BAT-файлы дополнительно проверьте в Windows.
Старые сообщения коммитов не изменены; новые исправления оформлены как Conventional/Scoped Commits.
